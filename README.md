# PPG 多设备无线采集控制台

一套用于**驾驶场景生理信号采集**的完整方案：5 块 ESP32 通过 ESP-NOW 组网，
同步采集三路 PPG（指端 / 手腕 / 对照）和两组六轴 IMU（手腕 / 方向盘），
由 macOS 上的图形界面统一完成连接、监控、录制和固件烧录。

界面的采集内核直接沿用原有的 `dual-imu` 采集脚本，波形、相关性算法和 16 列
数据格式都没有改动，只是把「插线 → 烧录 → 监控 → 存盘 → 归档」这条流程
收进了一个窗口。

## 系统组成

| 角色 | 数量 | 接的传感器 | 说明 |
| --- | --- | --- | --- |
| **Master** | 1 | 无 | 只插 USB。汇总四块从机的数据，按固定节奏从串口吐给电脑 |
| **Finger** | 1 | PPG ×1 | 指端 PPG |
| **Wrist** | 1 | PPG ×1 + IMU ×1 | 手腕 PPG 与手腕姿态 |
| **Other** | 1 | PPG ×1 | 对照 PPG（贴在别处或另一个人身上） |
| **Wheel** | 1 | IMU ×1 | 方向盘姿态 |

四块从机通过 **ESP-NOW** 把数据发给 Master，不需要路由器，也不需要配网。
Master 每 **48 ms** 输出一行 16 列数据（约 **20.8 Hz**），另外每 **500 ms**
输出一行 `@STATUS` 遥测行，用来判断谁在线、谁掉了。

```
Finger ─┐
Wrist  ─┤
Other  ─┼─ ESP-NOW ──▶ Master ── USB 串口 ──▶ 本程序 ──▶ CSV / MP4
Wheel  ─┘
```

`@STATUS` 和 `@MASTER_MAC` 这类标记行不会写进传感器 CSV，所以旧的采集脚本
读同一个串口也不会被打乱。

## 硬件与接线

每块板接什么、接哪个脚，完整版见 **[`ESP32状态固件/接线说明.md`](ESP32状态固件/接线说明.md)**。
按那张表接线就**不用改任何代码**。简版：

| 板子 | 接什么 | 脚位 |
| --- | --- | --- |
| Master | 只插 USB | — |
| Finger / Other | PPG ×1 | 信号 → **GPIO35** |
| Wrist | PPG ×1 + IMU ×1 | PPG → **GPIO35**；SDA → **21**，SCL → **22** |
| Wheel | IMU ×1 | SDA → **21**，SCL → **22** |

- PPG 必须是**模拟输出**型号（如 Pulse Sensor Amped），接 ADC 脚读 0–4095。
- IMU 的 I²C 地址固定按 **0x23** 读取。
- 引脚和上表不一样，就改对应固件里的那一行 `#define`，改完直接在界面里重烧，
  不用重启程序。

### 电量检测（默认关闭）

电池电压不能直接接 ESP32 引脚，必须先分压。配套固件出厂是关的：

```cpp
#define BATTERY_MONITOR_ENABLED 0
```

要用的话，先用两个 1% 精度的同值电阻做 1:2 分压：

```
电池正极 ── 100 kΩ ──┬── GPIO34
                     └── 100 kΩ ── GND
```

确认接好之后再改从机固件：

```cpp
#define BATTERY_MONITOR_ENABLED 1
#define BATTERY_ADC_PIN 34
#define BATTERY_DIVIDER_RATIO 2.0f
```

电阻比例不是 1:2 就要相应改 `BATTERY_DIVIDER_RATIO`，第一次最好拿万用表
量一次电池电压来校准。**没接分压线不要打开**，否则显示的百分比毫无意义。
关着的时候界面显示「电量未接」，不影响采集，也不会触发告警。

**需要：**

- macOS（见[已知限制](#已知限制)）
- Python **3.10 或以上**，且自带 `tkinter`
  （推荐 [python.org](https://www.python.org/downloads/macos/) 的官方安装包；
  Homebrew 的 `python3` 需要额外 `brew install python-tk`）

- **FFmpeg**（可选，只有勾选「同步保存波形录屏」时才需要）
- **arduino-cli** 或 **Arduino IDE**（可选，只有用界面烧录固件时才需要）
- CH340 / CP2102 等 USB 转串口驱动，看板子用的是哪颗芯片

```bash
git clone https://github.com/Jiaqi-Sun4691/wireless-ppg-daq.git
cd wireless-ppg-daq
python3 -m pip install -r requirements.txt
```

## 启动

三种方式，任选：

| 方式 | 怎么做 |
| --- | --- |
| **双击 App** | 双击 `PPG采集控制台.app`。首次 macOS 会问是否打开，选「打开」 |
| **双击脚本** | 双击 `启动采集界面.command`（会开一个终端窗口） |
| **命令行** | `python3 启动采集界面.py` |

> **从 GitHub 下载 ZIP 的话**，在访达里双击解压（用的是系统的 Archive Utility，
> 中文文件名没问题）。**不要用命令行的 `unzip`** —— GitHub 打的 zip 没有设
> UTF-8 文件名标志，Info-ZIP 会把中文名当成 CP437，一个中文文件都解不出来。
> 非要在终端解压就用 `ditto -xk 下载的.zip 目标目录/`。
>
> 解压之后 macOS 会给这些文件打「隔离」标记，双击 App 可能提示「已损坏」
> 或者「无法验证开发者」。在项目目录里执行一次：
>
> ```bash
> xattr -dr com.apple.quarantine .
> chmod +x 启动采集界面.command "PPG采集控制台.app/Contents/MacOS/PPGCollector"
> ```
>
> 用 `git clone` 的话没有这个问题。

在 macOS 上还有一点必须注意：python.org 的 `python3` 是 x86_64 + arm64 的
**通用二进制**，而 numpy 这类带原生扩展的包往往只装了本机架构那一份。
Apple 芯片上如果让它跑成 x86_64，`import numpy` 就会报
`incompatible architecture`。所以启动器会用 `arch` 显式钉到本机架构上
——判断硬件用的是 `sysctl hw.optional.arm64` 而不是 `uname -m`，后者在被
Rosetta 转译的进程里报的是进程架构，照着它钉正好钉在坏的那一半上。

前两种会自动去找一个能用的 Python：依次试 `PPG_PYTHON` 环境变量、
python.org 的 3.14→3.10、Homebrew、`/usr/local/bin`、`PATH` 里的 `python3`，
挑第一个同时装齐了 tkinter / pyserial / numpy / matplotlib 的。
找不到的话会直接告诉你缺哪个包、该敲哪条 pip 命令，而不是笼统地报「启动失败」。

想指定解释器：

```bash
export PPG_PYTHON=/path/to/python3
```

启动日志在 `~/Library/Logs/PPGCollector/launch.log`。

## 第一次使用：烧录固件

新买的板子是空的，得先把固件写进去。**「固件烧录」标签页**是一个向导，
全程不用打开 Arduino IDE，也不用手改任何 MAC 地址。

原理：四块从机要知道 Master 的 MAC 才能把数据发过去。向导会在烧完 Master
之后**自动从串口读出它的 MAC**，再在编译每块从机之前把这个 MAC 写进去。
`ESP32状态固件/` 里的源文件不会被改动，注入后的副本放在自动生成的
`已注入MAC的固件/` 目录里（同时也方便你用 Arduino IDE 手动烧）。

**步骤：**

1. **只**用 USB 接上 Master，点「烧录 Master」。
2. 烧完会自动读 MAC 并记住。读失败可以点「只读取 Master MAC」重试，
   或者手动输入 `AA:BB:CC:DD:EE:FF` 格式的地址。
3. 拔掉 Master，接上任意一块从机，在列表里点中它，点烧录。
4. 重复第 3 步，把四块从机烧完。

**顺序随便。** 除了「Master 必须先烧（或者你手里已经有它的 MAC）」之外，
剩下四块想先烧哪块就烧哪块，烧过的会在列表里打勾，四块都打上勾才算完成。
某块烧失败了，单独重烧那一块就行，不用从头来。

**MAC 记在设置里**，换台电脑或者重装程序之后，只要 Master 没换，直接烧从机就行。

### 烧录参数

默认是「自动识别（稳定优先）」。每换一块板都会重新识别芯片型号，
经典 ESP32 / S2 / S3 / C3 / C6 分开处理，不会拿 Master 的板型硬套给所有从机。

用的是一组偏保守的参数，目的是让参差不齐的板子都能烧进去：

| 参数 | 值 | 为什么 |
| --- | --- | --- |
| 上传速度 | 115200 | 比 921600 慢，但线材和 USB 芯片差一点也能过 |
| Flash 模式 | QIO | 实测通过的配置 |
| Flash 频率 | 40 MHz | 低频对 flash 颗粒的要求更低（S3 不暴露这个选项） |
| Flash 大小 | 4 MB | 绝大多数模组的最小公约数 |
| 分区表 | default | |
| PSRAM | disabled | 没有 PSRAM 的板子开了会起不来 |
| 调试等级 | none | |

碰到没见过的芯片型号，程序会**主动停下来**而不是硬烧。也可以在页面里手动
选 FQBN，这时会去查 `arduino-cli board details`，只把那块板真正支持的选项传进去
——第三方板子暴露的选项集经常不一样。

**烧录时的注意事项：**

- 一次只接一块板。
- 烧的过程中别拔 USB、别关程序。
- 提示连不上芯片：按住板子上的 `BOOT` 键再点烧录，看到开始写入了再松手。
- 必须用**能传数据**的 USB 线，充电线不行。

## 日常使用：一次采集的完整流程

1. USB 接上 Master（从机各自供电开机）。
2. 打开程序，选串口（一般会自动选中），点「连接设备」。
3. 「采集」页顶部填 **驾驶者 / 对照者 / 备注**。
4. 看五张状态卡是不是都绿了；用不到的设备取消勾选，它就不会参与告警，也不写进 CSV。
5. 点「开始采集」→ 弹窗确认这次记的是谁 → 确认。
6. 采。中途界面会实时画三路 PPG 波形和两两相关性。
7. 点「停止并保存」。

## 界面说明

五个标签页，按使用阶段分：

### 采集

一次采集从头到尾都在这一页：

- **被试信息**：驾驶者 / 对照者 / 备注。姓名会记住，下次自动带出来。
- **五张设备状态卡**：每块板的在线状态、距上次更新多久、电量（如果接了）。
  每张卡上有「写入 CSV」勾选框，决定这段数据存不存这个设备。
- **本次采集指标**：频率、样本数、**开始时刻**、时长、CSV 列选择。
  开始时刻是墙上时钟（`14:23:05`），停止后不清空——事后回填笔记、
  对行车视频的时间轴都要用它。
- **实时波形**：沿用原脚本的 400 点三路 PPG 曲线，Y 轴固定 0–4095，
  另有三组 3 秒滑窗相关性（指端↔手腕、指端↔对照、手腕↔对照）。
- **按钮**：连接 / 断开、开始采集、停止并保存。**所有操作都是按钮**，
  不需要按 `q` 或 `Ctrl` 组合键。

点「开始采集」后，设备勾选和姓名会被锁定，停止保存之后才能改。

### 串口与日志

- 上半：Master 的**逐行原始输出**，16 列数据和 `@STATUS` 都原样显示。
- 下半：程序运行日志（连接、烧录、保存、告警）。
- 可以暂停显示 / 继续 / 清空 / 关掉自动滚动。**暂停只是停止刷屏，
  后台采集和 CSV 写入照常进行。**

### 数据文件

列出保存目录里的历次采集：时间、**驾驶者 / 对照者**、样本数、时长、大小、
CSV 列数、有哪些设备、有没有录屏。

**直接在列表上操作**：

- **右键**任意一行 → 在访达中显示 / 打开 CSV / 播放实时录屏 / 播放重建录屏 /
  生成波形录屏 / 删除这次采集
- **双击** → 在访达中显示
- **Delete 或 Backspace 键** → 删除
- 按住 **⇧ / ⌘ 可以多选**，一次删掉好几次采集

删除是把**整个会话文件夹**（CSV、录屏，以及你自己放进去的行车视频、笔记）
移到**废纸篓**，不是直接抹掉，点错了还能捞回来。删除前会弹确认框，列出要删的
内容和总数据量——空采集和一小时的数据在列表里长得一样，这是最后一道防线。

下方按钮和右键菜单是同一组操作；多选时只有删除可用（"打开 CSV"对多选没有意义）。

### 固件烧录

见[上一节](#第一次使用烧录固件)。

### 设置

保存路径、文件名前缀、串口波特率、是否录波形、诊断阈值、告警声开关。

## 数据格式

### 一次采集 = 一个文件夹

```
PPG Data/
└── ppg_imu_data_2026-09-17_20-49-21/
    ├── ppg_imu_data_2026-09-17_20-49-21.csv
    ├── ppg_imu_data_2026-09-17_20-49-21.mp4     ← 勾了「保存波形录像」才有
    └── session.json
```

行车视频、同步标记、实验笔记都可以直接丢进对应那次的文件夹。
「在访达中显示」打开的就是这个文件夹。更早的平铺式旧文件仍然能被识别和列出。

**这段没收到数据的话，空 CSV 和整个文件夹会被自动删掉**，不会留一堆空壳。

### CSV 列

全选四个设备时是 19 列：

| 列 | 说明 |
| --- | --- |
| `timestamp(ms)` | Master 的毫秒时间戳 |
| `finger` / `wrist` / `other` | 三路 PPG 原始 ADC 值（0–4095） |
| `wrist_ax…wrist_gz` | 手腕 IMU 六轴 |
| `wheel_ax…wheel_gz` | 方向盘 IMU 六轴 |
| `system_time` | 电脑本地时间 |
| `driver_name` | 驾驶者姓名 |
| `other_name` | 对照者姓名 |

- **只勾了部分设备，就只写对应的列。** `timestamp(ms)`、`system_time`
  和两个姓名列始终保留。
- 每一行都立即 flush 到磁盘，拔线也不会丢一大段。
- 重复的时间戳会被跳过，界面上有计数。

> **为什么姓名要占两列？** 因为最终是把 CSV 单独分享出去做机器学习的。
> 多份文件 `pd.concat` 之后可以直接 `groupby("driver_name")` 按人划分
> 训练/测试集，不用另外读元数据文件。
>
> 列名用 `other_name` 而不是 `other`，是因为 `other` 已经是对照通道的
> PPG 数值列了。

### session.json

同一份信息也写一份在会话文件夹里，方便程序化读取：

```json
{
  "session": "ppg_imu_data_2026-09-17_20-49-21",
  "started_at": "2026-09-17T20:49:21",
  "ended_at": "2026-09-17T22:34:04",
  "driver": "张三",
  "other": "李四",
  "note": "市区，晚高峰",
  "devices": ["finger", "wrist", "other", "wheel"],
  "csv_columns": ["timestamp(ms)", "..."],
  "rows": 130898,
  "duration_seconds": 6283.1
}
```

## 波形录屏：采集完再生成

把界面上那条实时曲线做成 MP4，用来和行车视频并排对时刻。

在「数据文件」页选中某次采集 → **右键「生成波形录屏」**（或下方同名按钮），
后台渲染，底部显示进度，期间可以继续采集。

**两份录屏各存各的，互不覆盖**：

```
ppg_imu_data_2026-09-18_21-20-25/
├── ppg_imu_data_2026-09-18_21-20-25.csv
├── ppg_imu_data_2026-09-18_21-20-25.mp4              ← 采集时实时录的
├── ppg_imu_data_2026-09-18_21-20-25_重建.mp4          ← 事后从 CSV 生成的
└── ppg_imu_data_2026-09-18_21-20-25_重建_帧时间对照.csv
```

所以「播放实时录屏」和「播放重建录屏」是两个按钮，哪份存在哪个就能点。
重建**不会动**实时录的那份——两者内容不一样（实时的掉帧、播放偏快；重建的
时间轴准），留着让你自己挑。

**已经有录屏也能生成** —— 采集时实时录的那份恰恰最该重建（见下）。已经重建
过的再点也行，确认框会问是不是要覆盖上次重建的结果。只有两种情况按钮是灰的：
正在渲染另一次，或者这次采集没勾全三路 PPG（画不出原来那张图）。

列表里的「已重建」一栏显示这次有没有重建过。重建完又把那个 MP4 删了就显示
`—`，算没重建过。

也有命令行入口，适合批量补齐：

```bash
python3 重建录屏.py "某次采集的文件夹"
python3 重建录屏.py --all          # 补齐所有缺录屏的采集
```

两边调的是同一份 `ppg_collector/rebuild.py`，出来的视频一模一样。

渲染会自动切成几段并行跑（用性能核数量），再用 `concat -c copy` 拼起来
——不重新编码，拼接本身不损失画质。实测约 **400 帧/秒**，34 分钟的采集
约 1.6 分钟渲染完。

### 为什么不在采集时录

实时录屏靠界面定时器抓帧，渲染跟不上就掉帧。实测目标 20 fps 只抓到
**11~13 fps**，却按 20 fps 写盘：

```
真实采集 182 秒  →  录出来的视频只有 116 秒   （快 1.57 倍）
```

而且快多少取决于当时界面有多忙（告警响了、切了标签页、烧录页在刷新）。
所以**实时录屏里「第几帧对应几点」没有固定答案**，拿它和行车视频并排播
会越播越错开——正是这类录屏最主要的用途。

事后生成就没这个问题：第 k 帧固定对应采集开始后 k/20 秒，视频时长严格
等于采集时长，另外生成一份 `*_帧时间对照.csv`：

```
frame,video_seconds,timestamp(ms),system_time
0,0.0,606048,2026-09-18 21:20:25
1,0.05,606096,2026-09-18 21:20:25
```

标注时直接查表，不用猜。

其余几条：

| | 采集时实时录 | 事后生成 |
| --- | --- | --- |
| 帧↔时间对应 | 随负载变，不固定 | 固定，另附对照表 |
| 采集时 CPU 开销 | 每 50 ms 在主线程上编码一帧 | **零** |
| 失败时 | 静默失败，事后才发现 | 重跑一次就行 |
| 中途强杀程序 | MP4 没收尾，文件损坏 | CSV 已落盘，随时能再生成 |
| 换分辨率 / 帧率 | 只能重采一趟 | 改参数重跑 |

根本原因是：**视频是派生物，CSV 才是原件**。采集时掉一行数据不可逆，
少一个 MP4 不是——没理由让前者给后者让路。

仍然想要实时录的话，在「设置」里勾上「同步保存波形录屏 MP4」即可。

### 有一段恢复不了

事后生成时，每次采集**开头约 19 秒**的波形窗口是空的（留白，不画线）。
界面一连上设备就在画，点「开始采集」时那 400 点窗口早就满了，而 CSV 只从
开始采集那一刻记起——那段数据从没落过盘。

留白而不是补 0 是有意的：0 看着像信号掉到底，标注时会被当成真事件。

### FFmpeg

生成录屏要 FFmpeg：

```bash
brew install ffmpeg
```

**这里有个坑值得单独说**：macOS 双击启动 App 时给的 PATH 只有
`/usr/bin:/bin:/usr/sbin:/sbin`，而 Homebrew 装的 ffmpeg 在
`/opt/homebrew/bin`，不在里面。matplotlib 找不到它，录屏会**静默失败**。

所以程序不靠 PATH 找 ffmpeg，而是自己去 `shutil.which` 加 Homebrew /
MacPorts / 系统这几个常见位置挨个看，结果写进启动日志：

```
[ffmpeg] /opt/homebrew/bin/ffmpeg
```

「设置」页的录屏勾选框旁边也直接显示这个路径，找不到会标红。真勾了实时
录屏而又没有 ffmpeg，点「开始采集」会先弹窗问你，不会让你采完才知道。

## 在线检测与告警

### 判断依据

Master 每 500 ms 发一行 `@STATUS`，里面对四块从机各有四个字段：
**距上次收到数据多久（age）、传感器标志位（flags）、电池毫伏、包序号**。
程序据此分三层判断：

| 层 | 查什么 | 典型故障 |
| --- | --- | --- |
| **链路层** | `age` 超没超阈值 | 从机断电、跑出 ESP-NOW 距离、死机 |
| **传感器层** | `flags` 里的 PPG_OK / IMU_OK 位 | IMU 的 I²C 读不通、PPG 读数贴着 0 或 4095 |
| **数值层** | 数值多久没变过 | 板子还在发，但发的是卡住的旧值 |

**能定位到具体是哪个传感器。** 手腕板上同时挂了 PPG 和 IMU，程序把
`("wrist","PPG")` 和 `("wrist","IMU")` 分开计时，所以能告诉你是「手腕 IMU
读取失败」而不是笼统的「手腕掉线」。IMU 六个轴是当成一个整体比对的，
所以某一轴恰好长时间读数为 0 不会误报。

### 状态

| 状态 | 含义 |
| --- | --- |
| **在线** | 一切正常 |
| **数据延迟** | 收得到，但超过了延迟阈值 |
| **离线** | 超过离线阈值还没收到新包 |
| **IMU 读取失败** | 板子在线，但 I²C 读不通 —— 查供电、SDA、SCL、接触 |
| **PPG 异常** | ADC 贴着 0 或 4095 —— 通常是没接好或者饱和 |
| **数据未更新** | 数值长时间一动不动，从机或传感器卡住了 |
| **电量未接** | 固件没开电池 ADC（默认），正常状态 |
| **未启用** | 这个设备在卡上被取消勾选了，不参与告警 |

状态变化带**滞回**：变差立刻显示，恢复要稳定 600 ms 才认。
否则健康节点会因为 `@STATUS` 的 500 ms 节奏一直在阈值上下抖，闪个不停。
出于同样的原因，延迟阈值有下限，设低于协议周期的值是没有意义的。

### 告警

告警分两条线，因为这两类故障的性质不一样。

**掉线（链路断了）—— 立刻叫，一直叫。**
某块板一进入「离线」状态：

- 马上用**中文普通话**报出是谁：「指端模块离线」；
- **连续警笛**开始响，不是滴一声就完，一直响到它回来为止；
- 只要还没恢复，每 **30 秒**重播一次语音；
- 恢复了会说「指端模块已上线」，警笛同时停。

开车的时候不可能盯着屏幕，所以做成听得见、而且不会被忽略的。

**传感器故障（板子还在，但数据不对）—— 按持续时间三级升级。**
比如 IMU 的 I²C 读不通、PPG 贴着量程边界、数值卡住不动：

| 级别 | 持续时间 | 表现 |
| --- | --- | --- |
| 1 级 可能异常 | 1 秒 | 轻提示音。可能只是手指动了一下，不值得大惊小怪 |
| 2 级 持续异常 | 3 秒 | 提示音 + **语音说清是哪块板的哪个传感器**（「手腕的 IMU 读取失败」） |
| 3 级 确认故障 | 10 秒 | 更重的提示音 + 语音，每 20 秒重复一次，直到恢复 |

同时多个设备出问题时，只按最严重的那一级响一次，但日志里每一个都会记上。
界面底部一直显示当前最严重的那条。

取消勾选的设备完全不参与告警。告警声可以在「设置」里整体关掉（关掉会立刻停掉正在响的警笛）。

## 设置项

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 保存文件夹 | `~/Documents/PPG Data` | |
| CSV 文件名前缀 | `ppg_imu_data` | 后面自动接时间戳 |
| Plot 录像 | **关** | 采集时实时编码。默认关，改到事后按需生成（见下） |
| Slave 离线 | 2000 ms | 多久收不到包算离线，必须大于延迟阈值 |
| 延迟警告 | 800 ms | **下限 700 ms**（见下），低于它会被自动抬上来 |
| 数据卡住 | 2.0 秒 | 数值多久一动不动算卡住 |
| 故障提示音 | 开 | 关掉会立刻停掉正在响的警笛 |
| 报警确认 | 1.5 秒 | 异常持续这么久才报警，避免偶发丢包误报 |

改完点「保存设置」。填的值不合法（延迟 ≥ 离线、离线 ≤ 250 ms、卡住 < 0.5 秒）会被拒绝。

### 阈值为什么有下限

Master 每 500 ms 才发一条 `@STATUS`，所以两条状态之间，任何一个**完全正常**的
节点，它的「距上次收到数据」都会一路涨到接近 500 ms 才被清零。阈值要是定得比
这个节奏还紧，健康设备也会一直闪红。因此程序强制：

- 延迟警告 ≥ **700 ms**（= 500 + 200 余量）
- 离线 ≥ **1000 ms**，且必须大于延迟警告
- 数据卡住 ≥ **0.5 秒**

填了更小的值不会报错，但会被抬到下限，**并把抬完的值写回输入框**，同时在
「串口与日志」里记一条说明。所以界面上显示的数字永远就是实际在用的数字。

### 配置存在哪 —— 换台电脑要重新设吗

配置文件是 **`~/.ppg_collector_gui/settings.json`**，在你的**个人目录**下，
不在仓库里。里面存的是保存路径、文件名前缀、诊断阈值、告警开关、Master MAC、
上次用的串口、上次填的姓名。

所以：

- **仓库里不含任何人的配置。** clone 或解压之后是从代码里的默认值开始的，
  不会继承打包那台机器的路径，也不会拿到别人的 Master MAC。
- **默认保存目录是 `~/Documents/PPG Data`**，运行时按**当前登录用户**算出来
  ——张三跑就是 `/Users/zhangsan/Documents/PPG Data`，李四跑就是
  `/Users/lisi/Documents/PPG Data`。**不需要手动改，也不会因为找不到别人的
  家目录而报错。**
- **目录不存在会自动创建**（开始采集时连同本次的会话文件夹一起建）。
  「数据文件」页遇到不存在的目录就显示空列表，不会报错。
- 万一路径真的写不进去（选了只读位置、外接硬盘拔了），点「开始采集」会弹一个
  「无法开始采集」的提示并停下，不会采到一半才发现没存上。
- 想换到移动硬盘或者共享盘，点保存文件夹右边的「选择…」挑一个就行，会记住。

唯一需要同事自己填的是**串口**（各人的设备名不一样，但程序会自动发现并选中带
`usb` 字样的那个）和**要用的板子的 Master MAC**（如果用的是你这套板子，在
「固件烧录」页手动输一次；如果是他们自己的板子，烧 Master 的时候会自动读到）。

串口波特率固定 115200（与固件一致），界面上没有这一项。

## 已知限制

**目前只在 macOS 上跑过。** 核心的六个模块
（`protocol` / `serial_io` / `recorder` / `monitor` / `library` / `settings`）
没有任何平台相关调用，是干净可移植的。平台相关的部分集中在两个地方：

| 位置 | 用到什么 | 换到 Windows 要改成 |
| --- | --- | --- |
| `app.py` | `open`（在访达中显示 / 打开文件） | `os.startfile` / `explorer` |
| `app.py` | `afplay`（提示音、警笛） | `winsound.PlaySound` |
| `app.py` | `say`（中文语音播报） | SAPI（`pyttsx3` 或 PowerShell `Speech`） |
| `app.py` | `osascript`（启动失败弹窗） | 去掉即可 |
| `app.py` | `start_new_session` / `os.killpg`（管警笛进程） | `CREATE_NEW_PROCESS_GROUP` |
| `firmware.py` | Arduino IDE 的 macOS 安装路径 | Windows 下的对应路径 |

另外：

- 串口设备名按 macOS 的 `/dev/cu.*` 过滤（会剔掉蓝牙和调试口）。
- 启动脚本是 zsh 写的，Windows 下用 `python3 启动采集界面.py` 直接跑。

**如果 Master 烧的是旧版（不带 `@STATUS` 的）固件**，界面会显示「16 列兼容模式」：
数据照常保存，明显的波形卡死也能看出来，但**没法可靠判断某块从机是不是掉线了**
——旧 Master 收不到新包时会继续输出上一次的值。想要完整的在线检测，
就用本仓库 `ESP32状态固件/` 里的固件。
